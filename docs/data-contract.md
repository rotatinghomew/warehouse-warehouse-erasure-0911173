# 本地数据控制边界

来源别名、匿名person和仓内原始事件都是可定位身份的信息，样本均为本地合成。应用管理范围为指定root下的原始区、SQLite目录、列式文件和明确登记的导出；无法证明应用之外的任意用户备份已被擦除。调用方提供的export_person目标只有在显式以 `managed=True` 登记后才纳入删除证明，未登记目标仍由部署方自行处置，不能从路径名称猜测。

## 授权撤回与擦除

- `erasure.erase_person` 按 catalog、landing、facts、versions、exports 五个范围分步擦除，每个范围的状态与非个人证据（计数、改写后文件摘要）写入 `erasure_steps`。只有五个范围全部完成且 `verify_erasure` 基于实际存储扫描返回零残留时才报告 complete；任一范围失败会抛出带报告的 `ErasureIncomplete`，报告逐范围说明未完成项，可用 `resume_erasure` 续跑。
- 撤回的来源别名进入持久化 `suppressed_aliases` 抑制登记，别名映射本身从 `aliases` 移除。之后 `register`、`receive`、`publish` 和历史版本 `read` 都会拦截或过滤这些标识：旧报送重发、含旧标识的混批、检查点恢复都无法重新发布该人的记录；含受抑制标识的批次整体拒绝，不会让同批其他人重复入仓。
- 共享落地JSON和共享Parquet采用原子改写，只删除受抑制行，其他人记录保留；若文件仅含撤回者数据则删除文件并清空登记路径。组织级汇总不整批丢弃历史：`version_erasures` 保留每个固定版本的删前汇总、删后汇总与逐组织差额，`read` 返回的 `erasure_notices` 明确说明该历史版本因擦除而不可继续读取的部分。
- 新确认的别名通过 `suppress_alias` 扩展同一条擦除记录，已完成范围会重新对账。从较早检查点恢复后调用 `reconcile`：强制重跑全部范围、扫描 facts 目录中的孤儿Parquet，并以实际存储校验收尾；抑制登记在同一catalog内随恢复一起保留，因此恢复后读取固定版本依旧受限。
- 擦除证据不保存被删事件内容或个人标识明细，只保留计数、文件SHA256和范围状态，避免产生可重新识别个人的审计副本。仓外任意副本（未登记导出、用户自有备份）不在可擦除边界内，报告不把零行查询或请求受理当作擦除完成。
